## Step 7: إنشاء جسر Arduino USB Serial

**التاريخ:** 10 أبريل 2026
**الملفات المُستحدثة:** 4 ملفات جديدة

### المعمارية:

```
PX4 (ArduinoOutput driver)
    ↓ writes actuator PWM values
PTY slave (/dev/pts/X)
    ↓
PTY master ←→ arduino_pty_usb_bridge (bridge threads)
    ↓ USB bulk transfer (CH340)
Arduino Board (PX4_Arduino_Bridge.ino)
    ↓ PWM signals (pins 7,11,8,10)
ESCs → Motors
```

### الملفات المُستحدثة:

#### 1. `arduino_pty_usb_bridge.h` (25 سطر)
- واجهة C API للـ JNI
- دوال: `start()`, `stop()`, `get_slave_path()`

#### 2. `arduino_pty_usb_bridge.cpp` (290 سطر)
- **PTY creation:** `posix_openpt()` + `grantpt()` + `unlockpt()`
- **CH340 USB configuration:** baud rate, 8N1 line control
- **Thread 1 (PTY→USB):** reads actuator data from PTY, frames it with protocol `[0xAA][0x55][N][PWM...][checksum]`, sends via USB bulk transfer
- **Thread 2 (USB→PTY):** reads Arduino acknowledgments/telemetry, forwards to PTY
- **Protocol framing:** XOR checksum, big-endian PWM values

#### 3. `arduino_output.hpp` (65 سطر)
- PX4 driver class: `ArduinoOutput`
- Inherits `ModuleBase<ArduinoOutput>` + `OutputModuleInterface`
- Uses `MixingOutput` for uORB subscriptions and actuator mixing
- Max 16 channels

#### 4. `arduino_output.cpp` (220 سطر)
- **`updateOutputs()`:** receives PWM values from MixingOutput, builds protocol frame, writes to PTY slave
- **`Run()`:** work queue cycle, calls `_mixing_output.update()`, handles parameter updates
- **Protocol frame:** `[0xAA][0x55][N][ch0_H][ch0_L]...[checksum]`
- **PWM clamping:** 1000-2000 μs range
- **uORB publication:** publishes `actuator_outputs` for logging/debugging

### التعديلات على الملفات الموجودة:

#### `CMakeLists.txt`
```cmake
# Added to OUR_SOURCES:
arduino_pty_usb_bridge.cpp
arduino_output.cpp
```

#### `apps.cpp`
```cpp
extern "C" int arduino_output_main(int argc, char *argv[]);
apps["arduino_output"] = arduino_output_main;
```

#### `px4_jni.cpp`
1. **Includes:**
```cpp
#include "arduino_pty_usb_bridge.h"
#include "arduino_output.hpp"
```

2. **Driver startup (in `start_px4_modules()`):**
```cpp
// 10b. Start Arduino PTY bridge (from Java via setArduinoUsbFd)
// 10d. Start Arduino output driver (after PTY is ready)
const char *arduino_pty = arduino_pty_usb_bridge_get_slave_path();
if (arduino_pty) {
    ArduinoOutput::set_pty_path(arduino_pty);
    arduino_output_main(2, (char **)ard_argv);
}
```

3. **Driver shutdown:**
```cpp
// In stop_modules_only():
arduino_pty_usb_bridge_stop();

// In stopPX4():
arduino_pty_usb_bridge_stop();
```

4. **JNI function (for Java):**
```cpp
extern "C" JNIEXPORT void JNICALL
Java_com_ardophone_px4v17_bridge_PX4Bridge_setArduinoUsbFd(JNIEnv*, jobject, jint fd, jint baud) {
    if (fd >= 0) {
        arduino_pty_usb_bridge_start(fd, baud);
    } else {
        arduino_pty_usb_bridge_stop();
    }
}
```

### البروتوكول المُرسَل إلى Arduino:

| البايت | المحتوى |
|--------|---------|
| 0 | `0xAA` (Sync high) |
| 1 | `0x55` (Sync low) |
| 2 | عدد القنوات (N) |
| 3-4 | قناة 0 PWM (big-endian) |
| 5-6 | قناة 1 PWM |
| ... | ... |
| 2+1+N*2 | `checksum` (XOR of all previous bytes) |

### مثال عملي (4 محركات):
```
AA 55 04 03 E8 03 E8 03 E8 03 E8 XX
   ↑  ↑  └──── └──── └────┘ └────┘  ↑
Sync N   1000μs  1000μs  1000μs  1000μs  XOR
```

| البند | القيمة |
|-------|--------|
| ملفات جديدة | 4 |
| أسطر جديدة | ~590 سطر |
| بروتوكول Arduino | متوافق مع `PX4_Arduino_Bridge.ino` |
| معدل التحديث | ~50 Hz (MixingOutput default) |
| باود ريت | 115200 |
| عدد القنوات | حتى 16 |

### ⚠️ ملاحظات هامة:

1. **ترتيب البدء:** يجب استدعاء `setArduinoUsbFd()` من Java **قبل** بدء `startPX4()` حتى يكون الجسر جاهزاً عند بدء driver

## Step 8: إضافة كود Kotlin (USB + JNI Integration)

**التاريخ:** 10 أبريل 2026
**الملفات المُعدّلة:** 3 ملفات Kotlin

### الملفات المُعدّلة:

#### 1. `PX4Bridge.kt` — واجهة JNI

**قبل:**
```kotlin
external fun setServoUsbFd(fd: Int)           // ❌ حُذف
external fun setCanUsbFd(fd: Int)             // ❌ حُذف
```

**بعد:**

```kotlin
// Arduino USB Serial (CH340) — actuator output bridge
// Must be called BEFORE startPX4() so the driver can find the PTY path

```

#### 2. `UsbServoManager.kt` → `UsbDeviceManager.kt` — مدير أجهزة USB

**إعادة تسمية:** `UsbServoManager` → `UsbDeviceManager`

**تعديلات جوهرية:**

| العنصر | قبل | بعد |
|--------|-----|-----|
| اسم الكلاس | `UsbServoManager` | `UsbDeviceManager` |
| CH340 routing | `setCanUsbFd(fd)` → xqpower_can | `setArduinoUsbFd(fd, 115200)` → Arduino bridge |
| VID_CAN_LIN | ✅ مدعوم | ❌ محذوف |
| STM32 routing | `setServoUsbFd(fd)` | `setMavlinkTelemetryUsbFd(fd)` |

**الـ USB routing الجديد:**
```kotlin
when (device.vendorId) {
    VID_CH340 -> {
        PX4Bridge.setArduinoUsbFd(fd, ARDUINO_BAUD_RATE)  // ← جديد
    }
    VID_UBLOX, VID_PROLIFIC -> {
        PX4Bridge.setGpsUsbFd(fd)
    }
    VID_CP2102, VID_STM32 -> {
        PX4Bridge.setMavlinkTelemetryUsbFd(fd)
    }
}
```

#### 3. `FlightService.kt` — ترتيب بدء التشغيل

**التغيير الأهم:**
```kotlin
// ⚠️ مهم جداً: USB Manager يجب أن يبدأ قبل PX4
// حتى يكون جسر Arduino جاهزاً عند بدء arduino_output driver
usbDeviceManager.start()

PX4Bridge.startPX4(storagePath)

sensorReader.start()
```

**قبل (خاطئ):**
```kotlin
PX4Bridge.startPX4(storagePath)  // ← PX4 يبدأ أولاً
sensorReader.start()
usbServoManager.start()          // ← USB يبدأ بعد — متأخر جداً!
```

### ترتيب التشغيل الصحيح:

```
1. UsbDeviceManager.start()     ← يكشف Arduino CH340 + يفتح PTY bridge
2. PX4Bridge.startPX4()          ← يبدأ PX4 modules
   ↓
   2a. arduino_output driver    ← يقرأ PTY path من الجسر ويبدأ
   2b. باقي الـ modules
3. SensorReader.start()          ← يبدأ قراءة المستشعرات
```

### لماذا هذا الترتيب حرج؟

```
إذا بدأ PX4 أولاً:
  → arduino_output driver يبدأ
  → يبحث عن PTY path
  → PTY غير موجود (USB لم يُفتح بعد)
  → driver يفشل ❌

إذا بدأ USB أولاً:
  → Arduino CH340 يُكتشف
  → PTY bridge يُبدأ
  → PX4 يبدأ
  → arduino_output يجد PTY path ✅
```
