### 2.2 إعادة كتابة `arduino_output.cpp` — دالة `Run()`

```cpp
void ArduinoOutput::Run()
{
    if (should_exit()) {
        ScheduleClear();
        exit_and_cleanup();
        return;
    }

    actuator_test_s test;
    if (_actuator_sub.update(&test)) {
        // Check if it's a control action
        if (test.action == actuator_test_s::ACTION_DO_CONTROL) {
            // Determine which motor/channel this is for
            uint8_t channel_idx = 0;
            if (test.function >= actuator_test_s::FUNCTION_MOTOR1 &&
                test.function < actuator_test_s::FUNCTION_MOTOR1 + 8) {
                channel_idx = test.function - actuator_test_s::FUNCTION_MOTOR1;
            }

            // Build frame with 4 channels
            uint8_t frame[2 + 1 + (4 * 2) + 1];
            frame[0] = PROTO_SYNC_H;      // 0xAA
            frame[1] = PROTO_SYNC_L;      // 0x55
            frame[2] = 4;                 // Num Channels

            // Default all channels to 1000 (disarmed)
            for (int i = 0; i < 4; i++) {
                uint16_t pwm = 1000;
                if (i == channel_idx) {
                    // Convert value (-1 to 1) to PWM (1000-2000)
                    pwm = 1500 + (int)(test.value * 500);
                    if (pwm < 1000) pwm = 1000;
                    if (pwm > 2000) pwm = 2000;
                }
                frame[3 + i * 2] = (uint8_t)(pwm >> 8);
                frame[3 + i * 2 + 1] = (uint8_t)(pwm & 0xFF);
            }

            // Calculate Checksum
            uint8_t checksum = 0;
            for (size_t i = 0; i < 11; i++) {
                checksum ^= frame[i];
            }
            frame[11] = checksum;

            // Send to Arduino
            if (_uart_fd >= 0) {
                write(_uart_fd, frame, 12);
            }
        }
    }

    ScheduleDelayed(20_ms);
}
```

---

### 📐 تفاصيل البروتوكول

| البايت | المحتوى | الوصف |
|--------|---------|-------|
| 0 | `0xAA` | Sync High |
| 1 | `0x55` | Sync Low |
| 2 | `0x04` | عدد القنوات (4) |
| 3-4 | `PWM[ch0]` (big-endian) | المحرك الأول |
| 5-6 | `PWM[ch1]` | المحرك الثاني |
| 7-8 | `PWM[ch2]` | المحرك الثالث |
| 9-10 | `PWM[ch3]` | المحرك الرابع |
| 11 | `checksum` | XOR checksum |

**مثال:**
```
AA 55 04 | 05 DC | 03 E8 | 03 E8 | 03 E8 | XX
          ↑       ↑       ↑       ↑       ↑
          M1=1500 M2=1000 M3=1000 M4=1000 XOR
```

## 🔧 التعديل 3: إصلاح فتح PTY متأخر (UART FD = -1)

**الملف:** `arduino_output.cpp`
**المسار:** `app/src/main/cpp/arduino_output.cpp`

### المشكلة الأصلية:

عند تشغيل `arduino_output status` ظهرت:
```
Running, UART FD: -1, PTY: /dev/pts/0
```

وعند تشغيل `actuator_test` ظهر:
```
ERROR [px4] UART FD is -1, cannot send!
```

### السبب:

الـ PTY slave (`/dev/pts/0`) كان يُفتح في **الـ Constructor** (عند إنشاء الـ object)، لكن الجسر `arduino_pty_usb_bridge` لم يكن قد أنشأ الـ PTY slave بعد. النتيجة:
```cpp
// الكود القديم (خاطئ)
ArduinoOutput::ArduinoOutput() {
    _uart_fd = open(_device, O_WRONLY | O_NOCTTY | O_NONBLOCK);
    // _uart_fd = -1 لأن PTY slave غير موجود بعد!
}
```

### الحل:

نقل فتح الـ PTY إلى دالة `Run()` (دورة العمل) مع **إعادة محاولة** حتى ينجح:

```cpp
// الكود الجديد (صحيح)
ArduinoOutput::ArduinoOutput() {
    if (g_pty_path) {
        _device = g_pty_path;
        PX4_INFO("PTY path set to: %s (will open in Run)", _device);
        // لا نفتح PTY هنا — سنفتحها في Run()
    }
}

void ArduinoOutput::Run() {
    // محاولة فتح PTY في كل دورة حتى تنجح
    if (_uart_fd < 0 && _device != nullptr) {
        _uart_fd = open(_device, O_WRONLY | O_NOCTTY | O_NONBLOCK);
        if (_uart_fd >= 0) {
            PX4_INFO("Successfully opened PTY %s (fd=%d)", _device, _uart_fd);
        } else {
            PX4_WARN("Failed to open PTY %s (errno=%d) — will retry", _device, errno);
        }
    }

    // باقي الكود (استقبال actuator_test وإرسال)...
}
```

### التشخيصات المضافة:

تمت إضافة رسائل `PX4_INFO` و `PX4_WARN` لتتبع حالة الاتصال:

```cpp
PX4_INFO("actuator_test UPDATE: action=%d function=%d value=%.2f uart_fd=%d", ...);
PX4_INFO("Successfully opened PTY %s (fd=%d)", ...);
PX4_INFO("Sent %zd bytes to PTY (motor=%d, pwm=%d)", ...);
```

### الترتيب الصحيح بعد الإصلاح:

```
1. UsbDeviceManager.start()
   ↓
2. arduino_pty_usb_bridge_start() → ينشئ PTY slave (/dev/pts/0)
   ↓
3. arduino_output driver يبدأ
   ↓
4. Constructor: يحفظ المسار فقط (لا يفتح)
   ↓
5. Run() cycle 1: يحاول فتح /dev/pts/0 → ينجح ✅ (fd=35 مثلاً)
   ↓
6. Run() cycle N: يستقبل actuator_test → يرسل 12 بايت → Arduino → المحرك يدور 🚀
```

## 📌 ملاحظات هامة

1. **حل مؤقت للاختبار:** هذا التعديل يتجاوز `control_allocator` لغرض اختبار المحركات. للطيران الفعلي يجب إصلاح `control_allocator` بتحميل ملفات `init.d` أو تعيين المعاملات يدوياً.

2. **العودة للوضع الأصلي:** إذا أردت العودة للاعتماد على `control_allocator`:
   - استعد `arduino_output.hpp` لاستخدام `actuator_outputs`
   - استعد `arduino_output.cpp` للكود الأصلي
   - أصلح سبب `Unknown airframe`

3. **البروتوكول مطابق:** نفس البروتوكول الذي نجح في الاختبار من الحاسوب، لذا Arduino جاهز للاستقبال.

4. **معدل التحديث:** `20_ms` (50 Hz) — نفس معدل `MixingOutput` الافتراضي.

5. **إعادة المحاولة:** الـ driver يحاول فتح PTY في كل دورة (20ms) حتى ينجح. هذا يتحمل أي تأخير في إنشاء الجسر.

## 🔧 التعديل 4: إصلاح ازدواجية الإطار (Double Framing)

**الملف:** `arduino_output.cpp`
**المسار:** `app/src/main/cpp/arduino_output.cpp`

### المشكلة الأصلية:

عند إرسال الأمر، تظهر السجلات:
```
INFO [px4] Sent 12 bytes to PTY (motor=1, pwm=1750)
```
لكن المحرك لا يدور.

### السبب:

`arduino_output` كان يبني **إطار كامل** `[0xAA 0x55 0x04 PWM... checksum]` ثم يرسله للـ PTY.
لكن `arduino_pty_usb_bridge` (الجسر) كان **يُطّر الإطار مرة أخرى** بنفس التنسيق!

```
arduino_output → [AA 55 04 05 DC ... XX] (12 بايت) → PTY slave
       ↓
الجسر يقرأ 12 بايت من PTY master → يؤطرها مرة أخرى → [AA 55 0C AA 55 04 ...] 
       ↓
Arduino يتلقى بيانات خاطئة ويتجاهلها ❌
```

### الحل:

`arduino_output` يرسل الآن **قيم PWM الخام فقط** (8 بايت = 4 قنوات × 2 بايت)، والجسر يؤطرها:

```cpp
// قبل: إرسال إطار كامل (12 بايت)
uint8_t frame[12]; // AA 55 04 PWM0_H PWM0_L ... checksum
write(_uart_fd, frame, 12);

// بعد: إرسال قيم PWM الخام فقط (8 بايت)
uint8_t pwm_data[8]; // 4 قنوات × 2 بايت
for (int i = 0; i < 4; i++) {
    pwm_data[i * 2] = (uint8_t)(pwm >> 8);     // High byte
    pwm_data[i * 2 + 1] = (uint8_t)(pwm & 0xFF); // Low byte
}
write(_uart_fd, pwm_data, 8); // الجسر سيؤطر هذه البيانات
```

### النتيجة المتوقعة:

```
arduino_output → [05 DC 03 E8 03 E8 03 E8] (8 بايت خام) → PTY slave
       ↓
الجسر يقرأ 8 بايت → يبني إطار واحد صحيح → [AA 55 04 05 DC ... XX] (12 بايت)
       ↓
Arduino يتلقى الإطار الصحيح ✅
```

## 🔧 التعديل 5: إضافة دعم CDC-ACM (Arduino Mega/Uno الرسمي)

**الملف:** `arduino_pty_usb_bridge.cpp`
**المسار:** `app/src/main/cpp/arduino_pty_usb_bridge.cpp`

### المشكلة الأصلية:

```
ArduinoPtyUsb: CH340 write REG_BREAK1 failed
ArduinoPtyUsb: USB configuration failed
```

الجسر كان يحاول تهيئة الأردوينو كجهاز **CH340** فقط، لكن Arduino Mega 2560 الرسمي يستخدم بروتوكول **CDC-ACM** مختلف.

### الفرق بين CH340 و CDC-ACM:

| البند | CH340 | CDC-ACM (Arduino الرسمي) |
|-------|-------|--------------------------|
| VID | `0x1A86` | `0x2341` |
| التهيئة | يتطلب أوامر `usb_control` خاصة | لا يتطلب تهيئة خاصة |
| baud rate | يُضبط عبر `usb_control` | تُضبطه Java `UsbDeviceConnection` |

### الحل:

```cpp
// قبل: فشل إذا لم تنجح تهيئة CH340
if (!ch340_configure(fd, baud)) {
    if (r == 0) ioctl(fd, USBDEVFS_RELEASEINTERFACE, &iface);
    return false; // فشل ❌
}

// بعد: فشل CH340 = افتراض CDC-ACM
if (!ch340_configure(fd, baud)) {
    LOGI("CH340 config failed — assuming CDC-ACM device (Arduino Mega/Uno)");
    LOGI("CDC-ACM device ready (baud set by Java)");
    // لا نفشل — CDC-ACM يعمل بدون تهيئة خاصة ✅
}
return true;
```

## 🔧 التعديل 6: استبدال ioctl(USBDEVFS_BULK) بـ write() مباشر

**الملف:** `arduino_pty_usb_bridge.cpp`
**المسار:** `app/src/main/cpp/arduino_pty_usb_bridge.cpp`

### المشكلة الأصلية:

```
MavPtyUsb: usb bulk write fatal errno=25 (Inappropriate ioctl for device)
```

`USBDEVFS_BULK ioctl` لا يعمل مع أجهزة CDC-ACM على Android NDK.

### الحل:

استبدال `ioctl` بـ `write()` مباشر — يعمل مع كل أنواع أجهزة USB:

```cpp
// قبل: USBDEVFS_BULK ioctl (لا يعمل مع CDC-ACM)
struct usbdevfs_bulktransfer bulk {};
bulk.ep = 0x02;
bulk.len = frame_len;
bulk.data = frame_buf;
int r = ioctl(arduino_g_usb_fd, USBDEVFS_BULK, &bulk);

// بعد: write() مباشر أولاً، ثم ioctl كاحتياط (يعمل مع الجميع ✅)
ssize_t written = write(arduino_g_usb_fd, frame_buf, (size_t)frame_len);

if (written < 0 && (errno == EINVAL || errno == EOPNOTSUPP)) {
    static const uint8_t cdc_acm_endpoints[] = {0x02, 0x03, 0x01};
    for (uint8_t ep : cdc_acm_endpoints) {
        struct usbdevfs_bulktransfer bulk {};
        bulk.ep = ep;
        bulk.len = frame_len;
        bulk.timeout = 1000;
        bulk.data = frame_buf;

        int r = ioctl(arduino_g_usb_fd, USBDEVFS_BULK, &bulk);
        if (r >= 0) {
            written = bulk.len;
            break;
        }
    }
}
```

### لماذا هذه الاستراتيجية أفضل؟

1. **`write()` أولاً:** أسرع وأبسط، يعمل مع CH340 وبعض أجهزة CDC-ACM
2. **`ioctl` احتياط:** إذا فشل `write()` بـ `EINVAL`، نجرب endpoints مختلفة
3. **3 endpoints:** Arduino Mega يستخدم عادةً `0x02`، لكن نجرب `0x03` و`0x01` أيضاً
4. **لا فشل صامت:** نسجّل خطأ واضح إذا فشلت كل الطرق

## 🔧 التعديل 7: Java تُطلق واجهة USB (releaseInterface) لـ CDC-ACM

**الملفات المُعدّلة:**
- `UsbDeviceManager.kt` — إضافة `releaseInterface` لأجهزة Arduino
- `arduino_pty_usb_bridge.cpp` — سجل نجاح `ioctl`

### المشكلة الأصلية:

```
ArduinoPtyUsb: USB write failed: errno=22 (device disconnected?)
```

السبب: **Java `UsbDeviceConnection` تملك واجهة USB**، مما يمنع C++ من:
1. `USBDEVFS_CLAIMINTERFACE` → يفشل بـ `EBUSY`
2. `USBDEVFS_BULK` ioctl → يفشل بـ `EINVAL` لأن الواجهة غير مُدّعاة

### شرح المشكلة بتفصيل:

```
Java UsbDeviceConnection → تملك Interface 0
       ↓
C++ تريد write() أو ioctl(USBDEVFS_BULK) → مرفوض ❌
       ↓
errno=22 (EINVAL) — لا يمكن الكتابة على واجهة مملوكة
```

### الحل:

في `UsbDeviceManager.kt`، بعد الحصول على fd، نُطلق الواجهة لأجهزة Arduino CDC-ACM:

```kotlin
// For Arduino (CDC-ACM): release interface so C++ can claim it
if (device.vendorId == VID_ARDUINO) {
    try {
        val iface = device.getInterface(0)
        conn.releaseInterface(iface)
        Log.i(TAG, "Released CDC-ACM interface for C++ use")
    } catch (e: Exception) {
        Log.w(TAG, "Failed to release interface: ${e.message}")
    }
}
```

### الترتيب الجديد:

```
1. Java تفتح الجهاز → UsbDeviceConnection
2. Java تحصل على fd → conn.fileDescriptor
3. Java تُطلق الواجهة → releaseInterface(iface)
4. Java تمرر fd لـ C++ → setArduinoUsbFd(fd, 115200)
5. C++ تدّعي الواجهة → USBDEVFS_CLAIMINTERFACE ✅
6. C++ ترسل عبر ioctl(USBDEVFS_BULK) → Endpoint 0x02 ✅
```

### النتيجة المتوقعة:

```
INFO [px4] Sent 8 raw bytes to PTY (motor=1, pwm=1750)
INFO ArduinoPtyUsb: Sent 12/12 bytes to Arduino via EP 0x02  ✅
```

```cpp
static JavaVM* g_jvm = nullptr;
static jclass g_UsbDeviceMgrClass = nullptr;

static jint arduino_send_pwm_direct(const uint8_t* data, size_t len) {
    if (!g_jvm || !g_UsbDeviceMgrClass) return -1;

    JNIEnv* env = nullptr;
    bool attached = false;
    int status = g_jvm->GetEnv((void**)&env, JNI_VERSION_1_6);
    if (status == JNI_EDETACHED) {
        g_jvm->AttachCurrentThread(&env, nullptr);
        attached = true;
    }

    jbyteArray arr = env->NewByteArray((jsize)len);
    env->SetByteArrayRegion(arr, 0, (jsize)len, (const jbyte*)data);

    jmethodID mid = env->GetStaticMethodID(g_UsbDeviceMgrClass, "sendPwmDirect", "([B)I");
    jint result = -1;
    if (mid) {
        result = env->CallStaticIntMethod(g_UsbDeviceMgrClass, mid, arr);
    }

    env->DeleteLocalRef(arr);
    if (attached) g_jvm->DetachCurrentThread();
    return result;
}

extern "C" __EXPORT int arduino_send_pwm_via_java(const uint8_t* data, size_t len) {
    return arduino_send_pwm_direct(data, len);
}

JNIEXPORT jint JNICALL JNI_OnLoad(JavaVM* vm, void*) {
    g_jvm = vm;
    JNIEnv* env = nullptr;
    if (vm->GetEnv((void**)&env, JNI_VERSION_1_6) == JNI_OK) {
        jclass cls = env->FindClass("com/ardophone/px4v17/usb/UsbDeviceManager");
        if (cls) {
            g_UsbDeviceMgrClass = (jclass)env->NewGlobalRef(cls);
        }
    }
    return JNI_VERSION_1_6;
}
```

## 🔧 التعديل 10: طلب الواجهة الصحيحة (claimInterface على Interface 1)

**الملف:** `UsbDeviceManager.kt` — `openDevice()`

### المشكلة الأصلية:

```
Found OUT bulk EP: 0x04 on IF 1
sendPwmDirect: bulkTransfer to EP 0x04 len=12
sendPwmDirect: result=-1
```

Endpoint الصحيح (`0x04`) موجود على **Interface 1** لكن Java لم تطلبه (`claimInterface`). بدون طلب الواجهة، `bulkTransfer` يفشل.

### شرح بنية Arduino Mega USB:

| Interface | الوصف | Endpoints |
|-----------|-------|-----------|
| IF 0 | CDC Control (ACM) | Interrupt IN |
| IF 1 | CDC Data | **Bulk OUT (0x04)** + Bulk IN (0x83) |

### الحل:

طلب (claim) الواجهة التي تحتوي على endpoint الصحيح عند فتح الجهاز:

```kotlin
if (device.vendorId == VID_ARDUINO) {
    sArduinoConn = conn
    sArduinoDevice = device

    // Find and claim the interface with bulk OUT endpoint
    var claimed = false
    val ifaceCount = device.interfaceCount
    for (i in 0 until ifaceCount) {
        val iface = device.getInterface(i)
        for (j in 0 until iface.endpointCount) {
            val ep = iface.getEndpoint(j)
            if (ep.direction == UsbConstants.USB_DIR_OUT &&
                ep.type == UsbConstants.USB_ENDPOINT_XFER_BULK) {
                if (conn.claimInterface(iface, true)) {
                    Log.i(TAG, "Claimed IF $i for Arduino bulkTransfer (EP 0x${String.format("%02x", ep.address)})")
                    claimed = true
                }
                break
            }
        }
        if (claimed) break
    }
    if (!claimed) {
        Log.w(TAG, "Failed to claim any interface for Arduino bulkTransfer")
    }
}
```

### لماذا `claimInterface(iface, true)`؟

- **`true`** = force claim (حتى لو كان مستخدماً من kernel driver)
- بدون هذا، `bulkTransfer` يفشل بـ `-1` لأن الواجهة غير مدّعاة

### النتيجة المتوقعة:


```cpp
read_count++;
```

```cpp
    std::lock_guard<std::mutex> lock(arduino_g_response_mutex);

    // Keep only last 200 chars to avoid memory bloat
```

```cpp
extern "C" JNIEXPORT jstring JNICALL
Java_com_ardophone_px4v17_bridge_PX4Bridge_getArduinoResponse(JNIEnv* env, jobject) {
    const char* resp = arduino_get_last_response();
    return env->NewStringUTF(resp ? resp : "");
}
```
