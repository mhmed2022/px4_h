## 1️⃣ الخطوة 1: جهد الحساسات → قيم رقمية خام

### 🔍 ماذا يحدث بالضبط؟

#### 📡 الحساسات (Sensors)

```
العالم الفيزيائي
        ↓
حركة الطائرة (دوران، تسارع، مجال مغناطيسي)
        ↓
الحساسات تحول الحركة إلى جهد كهربائي (Voltage)
        ↓
ADC (Analog-to-Digital Converter)
        ↓
قيم رقمية خام (Raw Digital Counts)
```

#### 🧠 أنواع الحساسات

| الحساس | الوصف | ما يقيسه | النطاق |
|--------|-------|----------|--------|
| **Gyroscope** | الجايروسكوب | السرعة الزاوية (rad/s) | ±2000°/s |
| **Accelerometer** | التسارع | التسارع الخطي (m/s²) | ±16g |
| **Magnetometer** | المغناطيس | المجال المغناطيسي (μT) | ±1200μT |

#### 📐 عملية التحويل بالتفصيل

```
جهد الحساس (Analog Voltage)
        ↓
ADC (Analog-to-Digital Converter)
        ↓
تحويل من جهد إلى رقم

مثال للـ Gyroscope:
  الجهد = 1.65V (القيمة الصفرية)
  ADC Resolution = 16-bit
  Raw Value = (1.65 / 3.3) × 65536 = 32768

  إذا كانت الطائرة تدور:
    الجهد = 1.8V
    Raw Value = (1.8 / 3.3) × 65536 = 35725
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. القياس** | الحساس يحول الحركة إلى جهد |
| **2. التضخيم** | تضخيم الإشارة الضعيفة |
| **3. التحويل** | ADC يحول من Analog إلى Digital |
| **4. التخزين** | القيم تُخزن في寄存器 داخلي |
| **5. القراءة** | Driver يقرأ القيم عبر SPI/I2C |

## 2️⃣ الخطوة 2: Raw counts → قيم فيزيائية

### 🔍 ماذا يحدث بالضبط؟

#### 📐 التحويل من أرقام إلى فيزياء

```
Raw counts (int16/int32)
        ↓
sensor driver
        ↓
معادلة التحويل: value = (raw - offset) × scale
        ↓
قيم فيزيائية (rad/s, m/s², μT)
```

#### 🧮 معادلات التحويل بالتفصيل

**لـ Gyroscope:**

```
raw_value = 35725 (من الخطوة السابقة)

offset = 32768 (القيمة الصفرية)
scale = 0.000061035 (rad/s per count)  →  0.001064°/s per count

angular_velocity = (35725 - 32768) × 0.000061035
                 = 2957 × 0.000061035
                 = 0.180 rad/s
```

**لـ Accelerometer:**

```
raw_value = 40960

offset = 32768 (عند الراحة: 1g)
scale = 0.000488281 (m/s² per count)  →  0.00478g per count

acceleration = (40960 - 32768) × 0.000488281
             = 8192 × 0.000488281
             = 4.0 m/s²
```

**لـ Magnetometer:**

```
raw_value = 36000

offset = 32768
scale = 0.007324219 (μT per count)

magnetic_field = (36000 - 32768) × 0.007324219
               = 3232 × 0.007324219
               = 23.67 μT
```

#### 📝 كود التحويل (مبسط)

```cpp
// في sensor driver

float convert_gyro_raw_to_phys(int16_t raw) {
    const float offset = 32768.0f;
    const float scale = 0.000061035f;  // rad/s per count
    return (raw - offset) * scale;
}

float convert_accel_raw_to_phys(int16_t raw) {
    const float offset = 32768.0f;
    const float scale = 0.000488281f;  // m/s² per count
    return (raw - offset) * scale;
}
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. القراءة** | raw counts من الحساس |
| **2. التعويض** | طرح offset (القيمة الصفرية) |
| **3. التحجيم** | ضرب في scale factor |
| **4. النشر** | نشر عبر uORB |
| **5. النتيجة** | قيم فيزيائية حقيقية |

## 3️⃣ الخطوة 3: قيم غير مفلترة → قيم مفلترة

### 🔍 ماذا يحدث بالضبط؟

#### 📡 لماذا نحتاج التصفية؟

```
قيم فيزيائية خام
        ↓
ضجيج (Noise) من:
  - اهتزازات المحركات
  - تداخل كهربائي
  - حرارة
        ↓
تحتاج تصفية (Filtering)
        ↓
قيم نظيفة
```

#### 🔧 أنواع التصفية المستخدمة

| النوع | الوصف | الاستخدام |
|-------|-------|-----------|
| **Low-Pass Filter (LPF)** | يمرر الترددات المنخفضة | إزالة ضجيج الاهتزازات |
| **Notch Filter** | يزيل ترددات محددة | إزالة تردد المحركات |
| **Moving Average** | متوسط القيم السابقة | تنعيم الإشارة |

#### 📐 معادلات التصفية

**Low-Pass Filter:**

```
y[n] = α × x[n] + (1 - α) × y[n-1]

حيث:
  x[n] = القيمة الحالية
  y[n-1] = القيمة السابقة
  α = معامل التصفية (0.0 - 1.0)

مثال:
  α = 0.2
  x[n] = 0.180 rad/s (جديدة)
  y[n-1] = 0.150 rad/s (سابقة)

  y[n] = 0.2 × 0.180 + 0.8 × 0.150
       = 0.036 + 0.120
       = 0.156 rad/s
```

**Notch Filter:**

```
y[n] = b0×x[n] + b1×x[n-1] + b2×x[n-2] - a1×y[n-1] - a2×y[n-2]

الهدف: إزالة تردد 50Hz أو 100Hz (تردد المحركات)
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. الاستقبال** | قيم فيزيائية خام |
| **2. LPF** | تصفية الترددات العالية |
| **3. Notch** | إزالة ترددات محددة |
| **4. النتيجة** | قيم مفلترة |
| **5. النشر** | `sensor_*_fifo` topic |

## 4️⃣ الخطوة 4: بيانات حساسات متعددة → Quaternion

### 🔍 ماذا يحدث بالضبط؟

#### 🧠 EKF2 (Extended Kalman Filter)

```
قيم مفلترة من:
  - Gyro:  سرعة زاوية
  - Accel: تسارع خطي
  - Mag:   مجال مغناطيسي
        ↓
EKF2 (Extended Kalman Filter)
        ↓
دمج البيانات (Sensor Fusion)
        ↓
Quaternion (تقدير الاتجاه)
```

#### 📐 ما هو Quaternion؟

**Quaternion** = تمثيل رياضي للاتجاه في الفضاء 3D

```
q = [w, x, y, z]

حيث:
  w = cos(θ/2)
  x = sin(θ/2) × ux
  y = sin(θ/2) × uy
  z = sin(θ/2) × uz

(ux, uy, uz) = محور الدوران
θ = زاوية الدوران
```

**مثال:**

```
الطائرة مائلة 30° حول محور X

θ = 30° = π/6 rad
ux = 1, uy = 0, uz = 0

w = cos(15°) = 0.9659
x = sin(15°) × 1 = 0.2588
y = 0
z = 0

Quaternion = [0.9659, 0.2588, 0.0, 0.0]
```

#### 🧮 كيف يعمل EKF2؟

```
1. التنبؤ (Prediction):
   └─ Gyro يدمج مع الحالة السابقة
   └─ تقدير جديد

2. التحديث (Update):
   └─ Accel يقيس الجاذبية → يصحح الميل
   └─ Mag يقيس الشمال → يصحح الاتجاه

3. الدمج:
   └─ Kalman Gain يحسب الوزن الأمثل
   └─ دمج التنبؤ مع القياس

4. النتيجة:
   └─ Quaternion دقيق
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. التنبؤ** | Gyro يُدمج لتقدير الاتجاه |
| **2. القياس** | Accel + Mag يقيسان التصحيح |
| **3. التصحيح** | Kalman Filter يصحح الخطأ |
| **4. النتيجة** | Quaternion [w, x, y, z] |
| **5. النشر** | `vehicle_attitude` topic |

## 5️⃣ الخطوة 5: Quaternion → سرعة زاوية

### 🔍 ماذا يحدث بالضبط؟

#### 📐 التحويل

```
Quaternion [w, x, y, z]
        ↓
ekf2
        ↓
استخراج السرعة الزاوية
        ↓
rad/s
```

#### 🧮 المعادلة

```
dq/dt = 0.5 × q ⊗ ω

حيث:
  q = Quaternion الحالي
  ω = [0, ωx, ωy, ωz] (السرعة الزاوية)
  ⊗ = Quaternion multiplication

ωx, ωy, ωz = السرعة الزاوية حول كل محور
```

**مثال:**

```
الطائرة تدور حول محور Z بمعدل 0.5 rad/s

ωx = 0.0
ωy = 0.0
ωz = 0.5

النتيجة:
  angular_velocity = [0.0, 0.0, 0.5] rad/s
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. الاشتقاق** | d(q)/dt |
| **2. الاستخراج** | ω من معادلة Quaternion |
| **3. النشر** | `vehicle_angular_velocity` |
| **4. النتيجة** | [ωx, ωy, ωz] rad/s |

## 6️⃣ الخطوة 6: Quaternion → زوايا Euler

### 🔍 ماذا يحدث بالضبط؟

#### 📐 التحويل

```
Quaternion [w, x, y, z]
        ↓
ekf2
        ↓
معادلات التحويل
        ↓
Roll, Pitch, Yaw (radians)
```

#### 🧮 معادلات التحويل

```
Roll  (φ) = atan2(2×(w×x + y×z), 1 - 2×(x² + y²))
Pitch (θ) = asin(2×(w×y - z×x))
Yaw   (ψ) = atan2(2×(w×z + x×y), 1 - 2×(y² + z²))
```

**مثال:**

```
Quaternion = [0.9659, 0.2588, 0.0, 0.0]

Roll = atan2(2×(0.9659×0.2588), 1 - 2×(0.2588²))
     = atan2(0.5, 0.866)
     = 30° = 0.524 rad

Pitch = asin(2×(0.9659×0.0 - 0.0×0.2588))
      = asin(0.0)
      = 0°

Yaw = atan2(2×(0.9659×0.0 + 0.2588×0.0), 1 - 2×(0.0² + 0.0²))
    = atan2(0.0, 1.0)
    = 0°

النتيجة:
  Roll  = 0.524 rad (30°)
  Pitch = 0.0 rad
  Yaw   = 0.0 rad
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. الاستقبال** | Quaternion من EKF2 |
| **2. التحويل** | معادلات Quaternion → Euler |
| **3. النتيجة** | Roll, Pitch, Yaw |
| **4. النشر** | `vehicle_attitude` topic |

## 9️⃣ الخطوة 9: خطأ الاتجاه → Rate setpoint

### 🔍 ماذا يحدث بالضبط؟

#### 🧠 PID Controller

```
خطأ الاتجاه (radians)
        ↓
mc_att_control
        ↓
PID Controller
        ↓
Rate setpoint (rad/s)
```

#### 📐 معادلات PID

```
P = Kp × error
I = Ki × ∫error dt
D = Kd × d(error)/dt

rate_setpoint = P + I + D

مثال:
  Kp = 2.5
  error = 0.2 rad

  P = 2.5 × 0.2 = 0.5 rad/s

  (افتراض I و D صغيرة)

  rate_setpoint ≈ 0.5 rad/s
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. الاستقبال** | خطأ الاتجاه |

| **3. I** | تكامل الخطأ |
| **4. D** | مشتق الخطأ |
| **5. النتيجة** | Rate setpoint |
| **6. النشر** | `vehicle_rates_setpoint` |

## 1️⃣1️⃣ الخطوة 11: Rate error → Torque command

### 🔍 ماذا يحدث بالضبط؟

#### 🧠 Rate PID Controller

```
Rate error (rad/s)
        ↓
mc_rate_control
        ↓
PID Controller (Rate)
        ↓
Torque command (normalized)
```

#### 📐 المعادلات

```
P = Kp × rate_error
I = Ki × ∫rate_error dt
D = Kd × d(rate_error)/dt

torque = P + I + D

(يتم قصها إلى النطاق -1.0 إلى +1.0)

مثال:
  Kp = 1.0
  rate_error = 0.5 rad/s

  P = 1.0 × 0.5 = 0.5
  I = 0.1 × (0.5 + 0.4 + ...) = 0.15
  D = 0.05 × (0.5 - 0.3) = 0.01

  torque = 0.5 + 0.15 + 0.01 = 0.66
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. الاستقبال** | Rate error |
| **2. P** | ضرب في Kp |
| **3. I** | تكامل الخطأ |
| **4. D** | مشتق الخطأ |
| **5. القص** | قص إلى (-1.0, +1.0) |
| **6. النشر** | `vehicle_torque_setpoint` |

## 1️⃣2️⃣ الخطوة 12: Throttle input → Thrust command

### 🔍 ماذا يحدث بالضبط؟

#### 📐 التحويل

```
Throttle input (normalized)
        ↓
mc_rate_control
        ↓
تحويل إلى Thrust
        ↓
Thrust command (normalized)
```

#### 🧮 المعادلة

```
thrust = throttle_input × max_thrust

مثال:
  throttle_input = 0.7
  max_thrust = 1.0 (normalized)
```

## 1️⃣3️⃣ الخطوة 13: Torque + Thrust → Motor efforts

### 🔍 ماذا يحدث بالضبط؟

#### 🔄 control_allocator

```

        ↓

        ↓

        ↓
```

#### 📐 معادلات التوزيع

```

  pitch = 0.2
  yaw = 0.0

  motor[1] = 0.7 + 0.0 + 0.2 + 0.0 = 0.9
  motor[2] = 0.7 + 0.0 - 0.2 + 0.0 = 0.5
  motor[3] = 0.7 - 0.0 - 0.2 + 0.0 = 0.5
```

## 1️⃣7️⃣ الخطوة 17: PWM frame → USB bulk data

```
        ↓
```

#### 🧮 بناء الإطار بالتفصيل

```
قيم PWM:
  Motor 0 = 1950 = 0x079E
  Motor 1 = 1950 = 0x079E
  Motor 2 = 1750 = 0x06D6
  Motor 3 = 1750 = 0x06D6

الإطار:
  Index  | القيمة | الوصف
  -------|--------|------------------
  0      | 0xAA   | Header byte 1
  1      | 0x55   | Header byte 2
  2      | 0x04   | عدد القنوات (4)
  3      | 0x07   | Motor 0 High
  4      | 0x9E   | Motor 0 Low
  5      | 0x07   | Motor 1 High
  6      | 0x9E   | Motor 1 Low
  7      | 0x06   | Motor 2 High
  8      | 0xD6   | Motor 2 Low
  9      | 0x06   | Motor 3 High
  10     | 0xD6   | Motor 3 Low
  11     | 0x2A   | Checksum (XOR)
```

## 2️⃣0️⃣ الخطوة 20: تيار كهربائي → حركة ميكانيكية

### 🔍 ماذا يحدث بالضبط؟

#### 🚁 المحرك والحركة

```
تيار ثلاثي الطور (AC)
        ↓
Motor (Brushless DC)
        ↓
دوران المحرك (RPM)
        ↓
عزم الدوران (Torque)
        ↓
حركة ميكانيكية (الطائرة تتحرك!)
```

#### 📐 المعادلات الفيزيائية

```
RPM = speed_percent × max_RPM

مثال:
  speed_percent = 95%
  max_RPM = 10000

  RPM = 0.95 × 10000 = 9500 RPM
```

#### 🧮 تحليل الحركة

```
المحركات الأربعة:
  Motor 0: 95% → 9500 RPM
  Motor 1: 95% → 9500 RPM
  Motor 2: 75% → 7500 RPM
  Motor 3: 75% → 7500 RPM

فرق القوى:
  Front (M0 + M1) = 95% + 95% = 190%
  Rear  (M2 + M3) = 75% + 75% = 150%

النتيجة:
  Front > Rear
        ↓
  الطائرة تميل للأمام
        ↓
  الطائرة تتحرك للأمام!
```

#### ⚙️ ما يحدث بالتفصيل

| العملية | الوصف |
|---------|-------|
| **1. الاستقبال** | تيار ثلاثي الطور |
| **2. الدوران** | المحرك يدور (RPM) |
| **3. العزم** | Torque يتولد |
| **4. القوة** | المراوح تولد قوة |
| **5. الحركة** | الطائرة تتحرك! |

## ⚠️ ملاحظات هامة

1. **كل خطوة تحدث في وقت مختلف** - من قياس الحساس إلى الحركة قد يستغرق 10-50ms.

5. **PID Controllers** - يحول الأخطاء إلى أوامر تحكم.
