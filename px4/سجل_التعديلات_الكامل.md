# سجل التعديلات الكامل — مشروع PX4 Android + Arduino
**التاريخ:** 12 أبريل 2026

## ملخص التعديلات

تم تعديل **5 ملفات** لإصلاح مشاكل حرجة في مسار البيانات من QGroundControl → PX4 → Android → Arduino → المحركات.

---

## 1. arduino_output.cpp
**المسار:** `AndroidApp/app/src/main/cpp/arduino_output.cpp`

### التعديلات:

#### أ) إصلاح شرط PTY (كان يمنع التشغيل)
- **قبل:** الدرايفر يرفض البدء إذا لم يجد PTY path ← `PX4_ERR` ويتوقف
- **بعد:** يطبع `PX4_INFO("PTY not set — using Java bulkTransfer bridge")` ويكمل عادي

#### ب) إصلاح حساب PWM
- **قبل:** `pwm = 1500 + (ctrl * 500)` ← نطاق 1500-2000 فقط (خاطئ)
- **بعد:** `pwm = 1000 + (ctrl * 1000)` ← نطاق 1000-2000 (صحيح)

#### ج) معالجة NaN عند نزع التسليح
- **قبل:** لا يتحقق من NaN ← قيم عشوائية تُرسل للمحركات
- **بعد:** `if (!PX4_ISFINITE(ctrl)) pwm = 900` ← أقل من عتبة تسليح ESC

#### د) إضافة `#include <px4_platform_common/defines.h>`
- مطلوب لماكرو `PX4_ISFINITE`

#### هـ) إضافة دعم `actuator_test` topic
- **قبل:** يقرأ فقط من `actuator_motors` ← أمر `actuator_test set -m 1 -v 0.15` لا يعمل
- **بعد:** يقرأ من `actuator_test` أولاً (أولوية أعلى)، ثم `actuator_motors`
- أضيفت دالة `send_frame()` مشتركة لبناء وإرسال الإطار
- أضيف مصفوفة `_test_value[4]` لحفظ قيم الاختبار لكل محرك
- `print_status()` يعرض هل وضع الاختبار فعّال

## 4. usb_device_filter.xml
**المسار:** `AndroidApp/app/src/main/res/xml/usb_device_filter.xml`

### التعديل:
- **أُضيف:** Arduino Official VID
```xml
<!-- Arduino Official (Mega 2560, Uno R3) — VID 0x2341 = 9025 -->
<usb-device vendor-id="9025" />
```
- **السبب:** بدون هذا السطر، Android لا يتعرف تلقائياً على Arduino Official عند التوصيل

## 5. FlightService.kt
**المسار:** `AndroidApp/app/src/main/java/com/px4phone/flight/service/FlightService.kt`

### التعديل:
- **أُضيف:** تأخير 3 ثوانٍ بين بدء USB Manager وبدء PX4
```kotlin
usbDeviceManager.start()

// انتظار 3 ثوانٍ حتى يكتمل اكتشاف أجهزة USB والحصول على الإذن
// بدون هذا التأخير، arduino_output يبدأ قبل فتح اتصال Arduino
Thread.sleep(3000)

PX4Bridge.startPX4(storagePath)
```
- **السبب:** Race condition — `usbDeviceManager.start()` يسجل BroadcastReceiver (غير متزامن)، لكن `startPX4()` كان ينطلق فوراً قبل ما يُكتشف Arduino

## مسار البيانات بعد الإصلاح

```
QGroundControl
    ↓ (MAVLink عبر CP2102 radio)
Android Phone (PX4 v1.17)
    ↓ (actuator_test / actuator_motors uORB)
arduino_output driver
    ↓ (Java bulkTransfer عبر JNI)
UsbDeviceManager.sendPwmDirect()
    ↓ (USB CDC-ACM bulk OUT)
Arduino Mega 2560
    ↓ (Servo.writeMicroseconds)
ESCs → Motors
```

## أوامر الاختبار (MAVLink Console في QGC)

```bash
# اختبار محرك واحد (15% قوة)
actuator_test set -m 1 -v 0.15

# حالة الدرايفر
arduino_output status

# قراءة قيم المحركات
listener actuator_motors

# إيقاف الاختبار
# اضغط Enter
```

## ترتيب التشغيل الصحيح

1. افتح التطبيق
2. اضغط **Start**
3. وصّل **CP2102** (تلمتري) ← **Allow**
4. انتظر 3 ثوانٍ
5. وصّل **Arduino Mega** ← **Allow**
6. شغّل QGroundControl
7. اختبر المحركات من MAVLink Console
